# 服务端功能说明

这份说明用白话写：服务端**没有给用户点的页面**。它是一直开着的程序。

用户端（手机 / 网页）和管理端（电脑后台）把「登录、查课程、播放、开通会员、提现」这些请求发给它。它检查是否允许，把结果存进数据库；必要时再去问微信、支付宝、短信、对象存储这些外面的服务。

可以把它理解成总台。两个前台说的话，都由总台记账，并在需要时给外面的公司打电话。

---

## 它放在哪里、怎么访问

| 项目 | 说明 |
|---|---|
| 代码目录 | `mingxiang-server` |
| 启动类 | `com.sqx.SqxApplication`（控制台成功标志：`冥想项目启动成功`） |
| 数据库脚本 | `mingxiang-server/db/mingxiang.sql` |
| 建议库名 | `mingxiang` |
| 端口 | **9120** |
| 接口前缀 | 所有接口都在 `/sqx_fast` 下面 |
| 接口文档 | 浏览器打开 http://127.0.0.1:9120/sqx_fast/swagger-ui.html |

数据库里记的是：课程、章节、探索分类、用户、会员、订单、音效场景、邀请关系、站内消息、系统配置等。

Redis 在当前配置中**默认关闭**。若自行开启，可用于登录态、系统配置缓存等。

下面先说它为两个前台做哪些事，再说业务规则，最后说它会主动连接哪些外面的服务。

---

## 它为用户（用户端）做的事

这些都是用户在手机里点一下之后，由服务端完成的：

### 注册和登录

- 检查手机号和短信验证码，或检查密码。
- 微信小程序登录：用微信给的 code 换用户标识；可能还要绑定手机号。
- Apple 登录（App 场景）。
- 通过后发给用户一张登录凭证（JWT）。之后需要登录的请求都要带这张凭证，否则视为没登录。
- 找回密码：验证码通过后改密码。

### 首页

- 返回轮播图。
- 返回课程类型，以及每个类型下的推荐课程（封面、名称、副标题）。

### 探索与搜索

- 按探索一级分类（如冥想、睡眠、声音）和二级分类查询课程。
- 支持关键词搜索课程。

### 课程与章节

- 课程详情：名称、简介、封面、背景图、标签、导师头像 / 头衔 / 名称 / 简介。
- 章节列表：章节名、时长、音频地址、是否会员专享、是否上架。
- 相关推荐课程。

### 播放与学习记录

- 开始冥想 / 结束冥想：记下开始和结束时间，用来算时长。
- 「今日数据」：今日冥想、今日睡眠、今日专注。
- 累计登录天数、累计冥想时长。
- 最近播放列表。

### 喜欢

- 对课程点喜欢或取消。
- 「我的喜欢」列表从服务端读取。

### 助眠与音效

- 返回音乐场景 / 音效列表（名称、封面、音频），供夜间睡眠、专注时钟、日间小憩、正念呼吸页面播放。

### 会员与钱包

- 会员套餐列表、特权说明。
- 开通 / 续费：创建订单，对接微信 / 支付宝，支付回调后把用户标成会员并写到期时间。
- 钱包余额、资金明细。
- 提现申请：保存金额、收款账号；**不会自动打款**。

### 邀请推广

- 每个用户有邀请码。注册时可填别人的邀请码。
- 邀请人数、累计收益、团队列表（有推广比例的账号才能看团队）。

### 消息、客服、协议

- 站内系统消息列表、未读数量。
- 帮助文章、关于我们、用户协议、隐私政策、VIP 条款等文案（来自后台配置）。
- 在线客服跳转方式由后台配置。

### 文件上传

- 头像、课程封面、音频等。按配置存**本机目录**或 **阿里云 OSS**。

---

## 它为管理端做的事

- 工作人员登录：账号 + 密码 + 图片验证码。
- 数据中心：总用户、今日 / 本月 / 本年新增、总收入 / 今日 / 本月 / 本年收入等。
- 用户列表：查用户、看详情、启用 / 禁用、赠送会员、取消会员、删除。
- 注销信息：处理用户在 App 里提交的注销申请。
- 课程管理：课程增删改、上下架、章节（音频、是否会员专享）。
- 类型配置：冥想类型、标签、探索一二级分类。
- 音乐场景配置：助眠 / 专注用的音效。
- 订单中心：会员充值订单，按待支付 / 成功 / 失败筛选。
- 财务中心：提现审核、提现统计、支付统计、支付记录。
- 会员配置：套餐名称、月数、价格。
- 会员特权：特权名称、图标、排序（展示在用户端会员中心）。
- 首页装修：轮播图显示 / 隐藏。
- 帮助中心：分类和文章。
- 消息中心：给用户发站内消息；查看用户反馈。
- 系统配置：微信、支付宝、短信、文件上传、服务费、推送、开关、协议。
- 系统管理：管理员、角色、菜单。

## 业务规则（通俗说明）

### 看课和播放

1. 用户端首页、探索拉取**已上架**课程。未登录一般也能浏览公开内容。
2. 免费章节可直接播放。
3. 章节若标成会员专享：未开通会员的用户会看到锁，点开会引导开通会员。
4. 音频文件本身要能访问（地址有效）。地址失效时，页面能打开但播不出来。

### 学习统计

1. 用户点「开始」练习或开始播课程时，服务端记一条学习记录。
2. 点「结束」或播放结束时写入时长。
3. 「我的」页的今日冥想 / 睡眠 / 专注、累计冥想，都来自这些记录。

### 会员开通

1. 用户在会员中心选套餐（例如几个月多少钱）。
2. 服务端创建订单，向微信或支付宝下单，把拉起支付需要的信息交回手机。
3. 用户付完款，微信 / 支付宝访问服务端的通知地址。
4. 服务端核对之后，把订单改成已支付，给用户开通或续费会员。
5. 没配支付密钥时，按钮可能点了没反应，或提示失败。管理端也可以给某个用户「赠送会员」。

### 邀请和提现

1. 新用户注册填写邀请码后，和邀请人绑成关系。
2. 被邀请人开通会员等产生收益时，系统按后台规则给邀请人记账（以后台配置为准）。
3. 用户申请提现：只在库里生成一条待审核记录。
4. 工作人员在财务中心审核。**通过后系统不会自动把钱打到支付宝或微信**，仍需人工按用户填的收款信息打款。

### 喜欢、消息、协议

这些只改自己数据库，不连外面的公司。

## 对接了哪些外面的服务

下面每一项都是服务端**真的会向外发送请求**的。密钥没填时，它不会假装成功，用户端会看到失败提示。

密钥填在管理端「系统配置」（写入数据库），或服务端环境配置里。只在用户端页面上改文字，不会变成已经开通。

### 短信

注册、验证码登录、找回密码等由服务端发短信。工程支持模拟发送、短信宝、阿里云、腾讯云等，具体走哪一家以管理端「短信配置」为准。

- 腾讯云短信：https://cloud.tencent.com/product/sms
- 阿里云短信：https://www.aliyun.com/product/sms

没配密钥时：验证码发不出去。若后台开启模拟发送，可按说明填固定验证码（常见为 `123456`），方便本地测试。

### 微信登录

用户选择微信登录时，服务端用小程序 / 公众号 / App 的 AppId 与 Secret 换取用户标识。密钥在管理端「微信配置」中。没配好时，用户端会提示微信登录暂未开通。

微信公众平台：https://mp.weixin.qq.com/

### 微信支付 / 支付宝

用户开通会员时，服务端向微信或支付宝下单。支付完成后，对方访问服务端通知地址，服务端核对后再改订单、发放会员。

- 微信支付商户平台：https://pay.weixin.qq.com/
- 支付宝开放平台：https://open.alipay.com/

### 图片与音频存储

上传接口按配置走 **本机磁盘目录** 或 **阿里云 OSS**。OSS 未配好时，可先用本地上传路径联调。

阿里云 OSS：https://www.aliyun.com/product/oss

用户端上传头像、管理端上传课程封面和章节音频，都走这套接口（`/alioss/upload`）。

## 这些不是外面的公司

下面这些**只改自己的数据库**，不用申请微信、支付宝、短信账号也能用（前提是服务端和 MySQL 已启动）：

- 浏览库里已经有的课程、章节、轮播、探索分类
- 播放免费章节（音频文件本身要能打开）
- 夜间睡眠 / 专注时钟 / 小憩 / 呼吸的倒计时界面
- 喜欢、最近播放、今日数据、学习时长
- 会员权益标记、订单状态（真正收款仍需支付配置）
- 邀请关系记账、提现申请（真正打款需人工）
- 站内消息、帮助文章、协议文案
- 管理员、角色、菜单、操作相关权限

## 两个前台怎样和它配合

用户端和管理端都不直接「自己改数据库里的课程和订单」。它们把请求发给服务端，服务端再决定要不要去问微信、短信或图床。

所以：

1. **服务端没启动时**，两个网站都能打开界面，但登录、列表、播放、支付都会失败。
2. **外面的密钥**只配在服务端能读到的配置里。用户端没有地方填写微信支付商户号。
3. **管理端改完课程、会员套餐、轮播并保存后**，用户端下次请求才会用到新内容。用户端需要重新打开页面或下拉刷新。
4. **先启动服务端，再开管理端和用户端。** 三个窗口都要一直开着。

更细的页面说明见 [管理端功能说明](管理端-功能说明.md) 与 [用户端功能说明](用户端-功能说明.md)。怎么启动见 [服务端运行教程](服务端-运行教程.md)。
